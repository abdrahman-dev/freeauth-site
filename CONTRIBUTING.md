# Contributing

## Workflow

Every piece of work starts from an issue — no issue, no branch. If the work isn't captured yet, open a Task issue first.

- **Branch naming:** `type/short-description`, where `type` is one of `feat`, `fix`, `docs`, `chore`, or `design`. For example `fix/mobile-nav-overlap`.
- **Pull requests:** keep them small and focused on one issue, and link the issue in the body with `Closes #N` so it closes on merge.
- **Merging:** squash merge only. No direct pushes to `main`.
- **Visual changes:** follow `docs/ui-guide.md` for any UI or styling change.
- **AI coding agents:** follow `Agents/AGENTS.md` and stay within the scope of the issue — no opportunistic refactors or cleanups.
